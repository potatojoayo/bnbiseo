# 알림 시나리오 정리

> 최종 수정일: 2026-04-18
> 목적: 비엔비서 MVP에서 어떤 상황에 누구에게 어떤 알림을 보내야 하는지 역할별로 정리

## 1. 전제

- 역할은 `host(user)`, `manager`, `admin` 3가지다.
- 현재 핵심 도메인 상태는 아래 두 축이다.
- 숙소 상태: `pending_activation` -> `active`
- 청소 요청 상태: `pending_payment` -> `pending` -> `confirmed` -> `in_progress` -> `completed` 또는 `cancelled`
- 알림 채널은 우선순위를 아래처럼 본다.
- 1차: 앱 내 알림
- 2차: 카카오 알림톡 또는 문자
- 3차: 이메일
- MVP에서는 모든 이벤트를 다 보내기보다, 운영상 놓치면 안 되는 이벤트부터 넣는 게 맞다.

## 2. 역할별 알림 목적

### 호스트

- 청소 요청이 정상 접수됐는지 알기
- 매니저가 배정됐는지 알기
- 청소가 시작/완료됐는지 알기
- 취소 또는 환불처럼 일정에 영향 주는 변경을 바로 알기
- 숙소 등록이 완료돼 이제 청소 요청 가능해졌는지 알기

### 매니저

- 내가 새로 배정받은 청소가 있는지 바로 알기
- 오늘 처리해야 할 일정이 임박했는지 알기
- 호스트 취소나 일정 변경으로 헛걸음하지 않게 알기

### 관리자

- 새 숙소 등록 요청이 들어왔는지 알기
- 새 청소 요청이 들어왔는데 아직 매니저가 배정되지 않았는지 알기
- 취소, 긴급 청소, 진행 지연처럼 운영 개입이 필요한 상황을 알기

## 3. 필수 알림 시나리오

### 3.1 숙소 등록

| 이벤트 | 트리거 | 대상 | 내용 요약 | 우선순위 |
|---|---|---|---|---|
| 숙소 등록 접수 | 호스트가 새 숙소 생성 | admin | 새 숙소 등록 요청이 들어왔고 확인 필요 | 높음 |
| 숙소 등록 완료 | admin이 숙소를 `active`로 전환 | host | 숙소 등록이 완료되어 청소 요청 가능 | 높음 |

메모:
- `pending_activation` 상태 숙소는 청소 요청이 불가하므로, `active` 전환 알림은 호스트 입장에서 중요하다.

### 3.2 청소 요청 생성/접수

| 이벤트 | 트리거 | 대상 | 내용 요약 | 우선순위 |
|---|---|---|---|---|
| 청소 요청 결제 완료 | `pending_payment` -> `pending` | host | 청소 요청이 접수됐고 매니저 배정 대기 중 | 높음 |
| 청소 요청 신규 접수 | `pending_payment` -> `pending` | admin | 새 청소 요청이 들어와 배정 필요 | 높음 |
| 긴급 청소 신규 접수 | 당일 청소가 `pending`으로 생성 | admin | 긴급 청소 요청이 들어와 즉시 대응 필요 | 매우 높음 |

메모:
- `pending_payment` 단계는 결제 미완료이므로 알림 대상에서 제외하는 것이 맞다.
- 운영 관점에서는 `pending`부터 실요청으로 본다.

### 3.3 매니저 배정

| 이벤트 | 트리거 | 대상 | 내용 요약 | 우선순위 |
|---|---|---|---|---|
| 매니저 배정 완료 | `pending` -> `confirmed` | host | 담당 매니저가 배정되었고 일정이 확정됨 | 높음 |
| 매니저 배정 완료 | `pending` -> `confirmed` | manager | 새 청소 일정이 배정됨 | 높음 |
| 미배정 장기 대기 | `pending` 상태가 일정 시간 이상 지속 | admin | 아직 배정되지 않은 요청이라 확인 필요 | 높음 |

메모:
- `confirmed` 전환은 관리자 수동 배정과 매니저 직접 선점 둘 다 포함한다.
- 호스트에게는 매니저 이름, 예정 일시, 숙소 이름 정도가 포함되면 충분하다.

### 3.4 청소 진행

| 이벤트 | 트리거 | 대상 | 내용 요약 | 우선순위 |
|---|---|---|---|---|
| 청소 시작 | `confirmed` -> `in_progress` | host | 청소가 시작됨 | 중간 |
| 청소 시작 | `confirmed` -> `in_progress` | admin | 현장 작업 시작됨 | 낮음 |
| 청소 시작 임박 리마인드 | 청소 예정 1시간 전 또는 당일 아침 | manager | 곧 시작할 청소 일정 리마인드 | 중간 |

메모:
- 청소 시작은 필수는 아니지만, 호스트 입장에서는 체크인 준비 맥락상 유용하다.
- 관리자에게는 앱 내 운영 보드로 대체 가능하지만, 초기에는 알림도 유용하다.

### 3.5 청소 완료 / 리포트

| 이벤트 | 트리거 | 대상 | 내용 요약 | 우선순위 |
|---|---|---|---|---|
| 청소 완료 | `in_progress` -> `completed` | host | 청소 완료 및 사진/시설물 점검 리포트 확인 요청 | 매우 높음 |
| 청소 완료 | `in_progress` -> `completed` | admin | 작업 완료됨 | 낮음 |
| 이상 항목 포함 완료 | 완료 리포트 내 `caution` 또는 `defective` 존재 | host | 특이사항이 있어 리포트 확인 필요 | 매우 높음 |

메모:
- 호스트용 완료 알림은 가장 중요한 알림이다.
- 완료 알림은 단순 완료보다, 리포트 확인 CTA가 있는 형태가 적절하다.
- 점검 결과에 `caution`, `defective`가 있으면 일반 완료 알림보다 한 단계 더 강한 문구가 필요하다.

### 3.6 청소 취소

| 이벤트 | 트리거 | 대상 | 내용 요약 | 우선순위 |
|---|---|---|---|---|
| 호스트 취소 완료 | host가 요청 취소 후 `cancelled` 전환 | host | 취소 및 환불 처리 결과 안내 | 높음 |
| 호스트 취소 완료 | host가 요청 취소 후 `cancelled` 전환 | manager | 배정된 일정 취소 안내 | 높음 |
| 호스트 취소 완료 | host가 요청 취소 후 `cancelled` 전환 | admin | 취소된 일정 확인 | 중간 |
| 운영 취소/강제 취소 | admin이 `cancelled`로 변경 | host | 운영 사유로 일정 취소됨 | 매우 높음 |
| 운영 취소/강제 취소 | admin이 `cancelled`로 변경 | manager | 담당 일정 취소됨 | 높음 |

메모:
- `confirmed` 상태 취소는 매니저 이동/스케줄에 직접 영향이 있으므로 매니저 알림이 필수다.
- 환불 금액/환불 처리 여부는 호스트 알림에 포함되는 편이 좋다.

## 4. 권장하지만 후순위인 알림

### 숙소 등록 관련

| 이벤트 | 대상 | 이유 |
|---|---|---|
| 숙소 등록 후 24시간 경과 미처리 | admin | 등록 누락 방지 |
| 숙소 등록 완료 후 첫 청소 유도 | host | 전환율 개선용 |

### 청소 운영 관련

| 이벤트 | 대상 | 이유 |
|---|---|---|
| 청소 하루 전 리마인드 | manager, host | 일정 인지 강화 |
| 체크인 임박인데 아직 `in_progress` 미전환 | admin | 운영 개입 필요 |
| `in_progress` 장기 지속 | admin | 종료 누락 탐지 |
| 완료 후 24시간 내 리포트 미열람 | host | 리포트 확인 유도 |

## 5. MVP 기준 권장 구현 순서

### 1차

- 호스트: 청소 요청 접수
- 호스트: 매니저 배정 완료
- 호스트: 청소 완료
- 관리자: 새 청소 요청 접수
- 매니저: 청소 배정 완료

### 2차

- 호스트: 청소 시작
- 호스트: 취소/환불 완료
- 매니저: 배정 일정 취소
- 호스트: 숙소 등록 완료
- 관리자: 새 숙소 등록 접수

### 3차

- 긴급 청소 운영 알림
- 리마인드 알림
- 지연/미배정 감지 알림
- 특이사항 강조 완료 알림

## 6. 이벤트 기준 정리

실제 구현 시 이벤트 이름은 아래처럼 두면 관리가 쉽다.

| 이벤트 키 | 설명 | 대상 |
|---|---|---|
| `property.submitted` | 숙소 등록 접수 | admin |
| `property.activated` | 숙소 등록 완료 | host |
| `cleaning.requested` | 청소 요청 접수 | host, admin |
| `cleaning.urgent_requested` | 긴급 청소 접수 | admin |
| `cleaning.assigned` | 매니저 배정 완료 | host, manager |
| `cleaning.started` | 청소 시작 | host, admin |
| `cleaning.completed` | 청소 완료 | host, admin |
| `cleaning.completed_with_issue` | 특이사항 포함 청소 완료 | host |
| `cleaning.cancelled_by_host` | 호스트 취소 | host, manager, admin |
| `cleaning.cancelled_by_admin` | 운영 취소 | host, manager |

## 7. 알림 문구 예시

### 호스트

- 청소 요청이 접수되었어요. 매니저 배정 후 다시 알려드릴게요.
- `[숙소명]` 청소에 매니저가 배정되었어요.
- `[숙소명]` 청소가 완료되었어요. 사진과 시설물 점검 리포트를 확인해보세요.
- `[숙소명]` 점검 리포트에 확인이 필요한 특이사항이 있어요.
- 숙소 등록이 완료되었어요. 이제 청소를 요청할 수 있어요.

### 매니저

- 새로운 청소 일정이 배정되었어요.
- 담당 청소 일정이 취소되었어요.
- 곧 시작할 청소 일정이 있어요.

### 관리자

- 새 청소 요청이 접수되었어요. 매니저 배정이 필요해요.
- 긴급 청소 요청이 들어왔어요. 즉시 확인해주세요.
- 새 숙소 등록 요청이 들어왔어요.
- 아직 배정되지 않은 청소 요청이 있어요.

## 8. 구현 메모

- 상태 변경 시점에 직접 발송하지 말고, 이벤트를 먼저 기록한 뒤 채널별 발송기로 분리하는 구조가 안전하다.
- 같은 상태 변경이 중복 호출될 수 있으므로 idempotent 키가 필요하다.
- 앱 내 알림과 카카오 알림톡은 같은 이벤트를 공유하고, 템플릿만 채널별로 분리하는 편이 좋다.
- `completed` 알림은 리포트 URL을 함께 넣는 것이 핵심이다.
- 긴급 청소, 취소, 특이사항 포함 완료는 일반 알림보다 높은 우선순위로 다뤄야 한다.
